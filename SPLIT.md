# План на двоих · protocol / Launch Lab 21

База: текущий коммит `dfbe226` (модули, one-pager, роли уже есть).  
**Не пишем с нуля.** Улучшаем, чиним, локализуем под School 21 Узбекистан.

Общая цель на финише — один репозиторий, один демо-сценарий без конфликтов:

```
участник: создать/открыть → модуль → сохранить → one-pager
модератор: увидеть все команды и прогресс
```

---

## Роли людей (не путать с ролями в приложении)

| | Человек A | Человек B |
| --- | --- | --- |
| Фокус | Данные + модератор | Участник + живое демо |
| Главный вопрос | «Всё сохраняется и модератор видит всех?» | «Участник проходит сценарий без боли?» |
| На сцене | Второй заход: модератор | Первый заход: участник |

В приложении роли уже есть: `participant` / `moderator`.  
A усиливает сторону модератора.  
B доводит сторону участника.

## Жёсткое правило файлов

Каждый правит **только свою зону**. Чужой файл = конфликт при слиянии.

### Человек A — только эти файлы

| Файл | Что делать |
| --- | --- |
| `src/data/seed.ts` | Пиры Ташкент/Самарканд; ник + **отдельное ФИО**; 2–3 проекта с разным прогрессом модулей |
| `src/types.ts` | Только если нужны поля (кампус enum, cohort `25_12_TAS`). Не ломать `answers` / `ModuleId` без сообщения B |
| `src/store.tsx` | Права модератора, save/load, баги сохранения. Не переименовывать `saveAnswer` / `createProject` без сообщения B |
| `src/lib/modules.ts` | Тексты модулей/подсказок, логика `doneCount` / unlock. Порядок и id модулей не менять без B |
| `src/pages/Moderate.tsx` | Панель: все команды, прогресс, ссылки на проект/one-pager, комментарии если успеете |
| `src/pages/Analytics.tsx` | По желанию: обзор для модератора |
| `src/lib/labels.ts` | Подписи ролей/статусов, если нужны |

### Человек B — только эти файлы

| Файл | Что делать |
| --- | --- |
| `src/pages/ProjectPage.tsx` | Форма модуля, «Сохранить», прогресс, текущий модуль |
| `src/pages/OnePager.tsx` | Автосборка из answers, читаемость для жюри |
| `src/pages/NewProject.tsx` | Создание проекта: название, команда, описание |
| `src/pages/Feed.tsx` | Список «мой проект» / обзор для участника |
| `src/pages/Login.tsx` | Понятный вход: участник vs модератор, подсказки демо |
| `src/components/Layout.tsx` | Навигация участника (не ломать ссылку модератора) |
| `src/components/ProjectCard.tsx` | Карточка с прогрессом модулей |
| `src/components/ui.tsx` / `Logo.tsx` | Мелкий UI, только если нужно для сценария |

### Общие файлы — особый режим

| Файл | Кто | Как |
| --- | --- | --- |
| `src/App.tsx` | Почти никто | Роуты уже есть. Трогать только если добавляете новый путь — написать напарнику |
| `README.md` | Вместе в конце | 5 минут на демо-инструкцию |

## Контракт данных (не ломать)

Это общий язык. Менять только по согласованию.

### Пир

```ts
nickname  // Intra-ник: stockcol
name      // отдельное ФИО, НЕ «расшифровка» ника
campus    // Ташкент | Самарканд
cohort    // например 25_12_TAS
```

### Проект

Уже есть и нужно сохранить:

- `title`, `teamName`, `pitch`
- `memberIds`, `ownerId`
- `answers: Record<ModuleId, Record<fieldId, string>>`
- `pagerNote` (опционально)

### API store, которое B вызывает как есть

```ts
saveAnswer(projectId, moduleId, fields)
createProject(...)
updateProject(...)
projects / peers / currentUser / isModerator
```

A может улучшать внутри, но **сигнатуры не ломает** без сообщения в чат.

### Модули

Сейчас 6 штук: `problem`, `audience`, `solution`, `wedge`, `ask`, `next`.  
Минимум по ТЗ — 3. **Не удалять id**, пока B не готов: иначе сломаются сиды и формы.

Хелперы, которые B уже использует:

- `MODULES`, `doneCount`, `isModuleDone`, `isUnlocked`, `currentModuleId`
- `canAccessProject`, `moduleLines`

## Задачи Человека A (подробно)

### Must (обязательно до слияния)

1. **Сиды под Узбекистан**
   - Кампусы: Ташкент, Самарканд
   - Ники в стиле Intra (`stockcol`, …)
   - `name` = отдельное реальное ФИО
   - cohort вроде `25_12_TAS` / `25_12_SAM`
   - ≥ 2 проекта: один почти пустой, один с 2–3 заполненными модулями (для демо модератора)

2. **Сохранение**
   - Проверить: save → F5 → ответы на месте
   - При смене модели поднять `STORAGE_VERSION`
   - Пароль демо оставить простым (сейчас `21`) или явно написать в README

3. **Модератор**
   - `/moderate`: все проекты, прогресс `N/6`, текущий модуль
   - Открыть чужой проект и one-pager
   - Участник по-прежнему не видит чужие ответы

### Nice (если останется время)

- Комментарий модератора к проекту (поле в project + UI в Moderate)
- Analytics понятнее для сотрудника лаба
- Фильтр команд по кампусу Ташкент / Самарканд

### Не делать

- Не переписывать `ProjectPage` / `OnePager`
- Не менять тексты кнопок «Сохранить» у B без нужды
- Не пилить новую соцсеть / scout

### Демо-скрипт A (30–40 сек на сцене)

1. Войти как модератор (ник из сидов + роль модератор)  
2. Открыть «Модерация» → видно прогресс команд  
3. Открыть проект → ответы / one-pager

## Задачи Человека B (подробно)

### Must (обязательно до слияния)

1. **Сценарий участника без спотыканий**
   - Login → свой проект (или создать)  
   - Выбрать модуль → заполнить поля с подсказками  
   - «Сохранить ответ» → видно, что сохранилось  
   - Перейти в One-pager → те же ответы на месте  

2. **Профиль проекта**
   - Название, команда, краткое описание редактируются понятно

3. **Прогресс на экране**
   - Видно сколько модулей закрыто и какой текущий
   - Нельзя «перепрыгнуть» заблокированный модуль (логика уже есть — не сломать)

4. **Login**
   - Ясно: войти как участник / как модератор
   - Подсказка демо-аккаунта (после сидов A — обновить текст)

### Nice

- Красивее one-pager для показа жюри
- Меньше шума на Feed для участника («Мой проект» первым)
- Пустые состояния с понятным hint

### Не делать

- Не менять `seed.ts` / структуру `answers`
- Не ломать `canAccessProject`
- Не уводить час в People/Scout

### Демо-скрипт B (1,5–2 мин на сцене)

1. Войти участником  
2. Открыть/создать проект  
3. Заполнить модуль → сохранить  
4. One-pager → показать автосборку

## Как совместить без боли

### До старта (5–10 минут вместе)

1. Открыть этот файл.  
2. A говорит: какие ники будут в сидах для демо.  
3. B записывает их в текст Login.  
4. Договориться: **не переименовывать** `saveAnswer`, id модулей, роуты:
   - `/project/:id`
   - `/project/:id/onepager`
   - `/moderate`
   - `/new`

### Во время работы

- Ветки (если есть git):

```text
main
├── person-a   # только зона A
└── person-b   # только зона B
```

- Без веток: кидать **только свои файлы** напарнику списком из таблицы выше.  
- Раз в ~20 минут короткий sync в чат: «saveAnswer не трогал» / «сиды готовы: nick1, nick2».

### Слияние (10 минут, порядок важен)

1. Сначала влить **A** (сиды + store + moderate).  
2. Потом влить **B** (экраны участника).  
3. Если конфликт в редком файле (`Layout`, `labels`) — править вместе 2 минуты.  
4. `npm run dev` → прогон чеклиста ниже.  
5. Если экран «старый» — сбросить демо / поднять version уже сделал A.

### Чеклист после слияния (оба)

- [ ] Участник: создать или открыть свой проект  
- [ ] Участник: заполнить модуль → сохранить → F5 → ответ жив  
- [ ] Участник: one-pager показывает этот ответ  
- [ ] Участник: чужой проект закрыт  
- [ ] Модератор: видит все команды и прогресс  
- [ ] Модератор: открывает чужой one-pager  
- [ ] Ник и ФИО на профиле оба видны и это разные поля  
- [ ] В сидах есть Ташкент и Самарканд  

Если любой пункт красный — чинить вместе, не пилить новые фичи.

## Definition of Done

Считаем готовым, если:

1. Обязательный сценарий участника работает целиком.  
2. Модератор видит прогресс всех команд.  
3. Данные не теряются после reload.  
4. Код склеен в один `main` без «у меня локально другое».  
5. Оба могут провести свой кусок демо без подсказок с листа.

## Коротко

- **A** = сиды, сохранение, модератор.  
- **B** = путь участника и one-pager на экране.  
- Общее = не ломать `answers`, `saveAnswer`, роуты, id модулей.  
- Слияние = сначала A, потом B, потом общий чеклист.  
- Бонусные фичи — только после зелёного чеклиста.
